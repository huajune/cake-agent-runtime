## 2. 范围与风险

### 变更摘要

- 报名十字段（姓名/电话/性别/年龄/学生身份/学历/健康证/身高/体重/户籍省份）统一 Claim 化：模型提交候选人资料须附原话 quote，纯确定性裁决器验证出处与值（证据化方案 §4-§12 主体，shadow 首发）。
- precheck 新增 `candidateClaims` 带证据入参与 `factAdjudication` 裁决视图；裁决即存 PrecheckSnapshot 到 Redis（TTL 2h，precheckId 按 turnId 幂等）。
- booking 新增 `precheckId` 可选入参：对账最终 payload 与预检快照（七字段等价 + 消息水位 + jobId），shadow 只记差异不拦截。
- `[用户档案]` Prompt 段新增"已失效历史资料"渲染：本会话有更新值的历史字段只声明失效、不渲染旧值（本次唯一立即生效的行为变化）。
- 新增观测事件 `fact_adjudication` 落 `agent_execution_events`（PII 纪律：不携带字段值与 quote 原文）。
- 新增可选环境变量 `CANDIDATE_FACT_ADJUDICATION_MODE`（默认 shadow，未配置时行为零变化）。

### 高风险区域

- P0：shadow 承诺——precheck 收资清单与 booking 提交行为必须与 v10.38.0 逐字节一致（裁决全链 try-catch fail open，异常只降级不阻断）。
- P1：`[用户档案]` 已失效段的字符串比较假阳会使历史字段不展示；失败方向安全（历史值本就只许待确认使用），最坏为模型多问候选人一句。
- P1：`candidateClaims` zod 数组校验失败会拒整个 precheck 调用，模型可能换格式重试空转（6a448d09 同型先例）；tool_call error 可观测，可热修放宽 preprocess。
- P1：Redis 快照写入与 events 落库均为 fire-and-forget，失败仅 warn 不影响主链路；"裁决静默失灵"由日观测任务第 0 步分诊兜底（有 precheck 调用却零事件 = 链路断标 P0）。
