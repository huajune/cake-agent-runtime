## 2. 范围与风险

### 变更摘要

- 收资追问次数改为按单个字段、按实际发出的 assistant 问句统计，同回合工具重试不重复计数。
- 候选人补齐耗尽字段后清除对应 `ask_limit_exhausted`；旧表单首次加载时迁移不可信计数。
- 持久化报名资料复述确认，跨回合选择面试时间仍可继续预约；资料或契约变化会使旧确认失效。

### 高风险区域

- P0：收资状态机错误可能造成候选人被提前转人工，或已经问满后继续第三次追问。
- P0：复述确认跨回合丢失可能阻断预约工具调用。
- P1：旧 Redis 表单迁移必须保留已填资料和非追问类升级原因。

### 部署顺序与回滚

- 部署顺序：应用镜像单步更新，无前置 migration/config 动作。
- 回滚版本：`v11.0.1`。
- 回滚条件：报名异常转人工、同项出现第三次追问、复述确认后仍无法进入预约，或健康检查失败。
- 回滚动作：使用现有部署工作流恢复 `v11.0.1` 镜像；Redis 表单版本迁移向后兼容，旧应用忽略新增字段。
