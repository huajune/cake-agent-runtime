## 2. 范围与风险

### 变更摘要

- 收口候选人事实可信度与隐私边界：修复截断 quote、图片描述作证、手机号复述确认、证件号脱敏、真名问答、籍贯主动追问以及脏城市污染。
- 收口预约与回复守卫：禁止工具调用 XML 残片外泄，统一爽约取消时点，约面成功必须播报日期，修复在途工单改约假确认，并补齐 booking 拒绝码观测。
- 按运营与海绵 `cooperationMode` 契约更新薪资、健康证、食宿、发薪主体和签约主体的自答/转人工边界；字段缺失时保持安全降级。
- 将记忆、Redis schema、守卫、工具、收资和展示词表收拢为单一真相源，增加 `vocab:validate`，并清理已确认的死代码、过时类型和注释。
- 修复测试批次取消态、预约 fixture、治理文档按日聚合，以及飞书重试和 Supabase keep-alive 定时任务时区。
- #966 移除被跟踪的本机 Claude settings，建立无密钥共享安全基线，并收紧 pnpm/Docker 依赖生命周期脚本策略。

范围边界：v10.40.0 发布结果补记 #903/#906 以及自动生成的 release metadata 只用于历史治理，
不进入本版本候选人/运营可感知摘要和发版通知。当前发版准备 PR 已从 pending metadata 移除
#903/#906，补齐 #911/#914/#913/#931/#912，并把业务摘要收敛为 10 条可感知改动。

### 高风险区域

- **P0｜凭据与供应链**：从 Git 删除明文配置不等于撤销已泄漏凭据；暴露的 Supabase、飞书、Stride 和 API 凭据必须完成轮换或失效确认。pnpm `strictDepBuilds` / `allowBuilds` 调整可能让干净安装或原生依赖构建失败。
- **P0｜候选人主链路**：事实裁决、手机号/籍贯/城市、约面与改约、工具残片守卫均直接影响候选人回复、档案与工单状态，必须用真实 Agent 链路验证，不能只依赖单测。
- **P0｜咨询口径**：BPO/RPO 映射的发薪主体与签约主体分支不对称；内部术语泄漏、错误自答或漏转人工均为发布阻断。
- **P1｜外部服务与定时任务**：Sponge 新字段、飞书错误码重试集合、清理任务和 Supabase keep-alive 时区需在生产观测；失败不涉及 schema，但可能造成错误重试或保活缺口。
- **P1｜大范围重构**：词表和死代码清理跨越 memory、guardrail、tools、test-suite 等域，单 PR 已有行为等价证据，仍需以最终 release head 跑完整 CI。
