## 2. 范围与风险

### 变更摘要

- 升级 AI SDK v7 及各 Provider，增加 fast/deep 思考分档、运行时 effort 和可配置模型降级链；收缩模型注册表到各厂商最新在售档位。
- 图片轮改为直达视觉候选模型，保留图片可见性；修复 AI SDK v7 的消息、工具调用及测试契约兼容。
- 生产 Docker 与 GitHub Actions 从 Node 22 切换到 Node 24，`engines >=22` 保持本地兼容。
- 预约成功后继续自动发送兼职岗位信息群，并明确它不是面试群；单独面试群由同一企微身份使用将来时话术承接。
- 面试群待补发时产生 `interview_group_invite_required` 接管事件；候选人回复送达后暂停托管并提醒补发。
- 出站硬规则拦截兼职群/面试群混淆、面试群虚假已发送及工作人员、运营、人工、同事、机器人等身份暴露话术。

### 高风险区域

- P0：AI SDK 主版本升级涉及所有模型调用、流式消息、工具调用和多模态输入，失败可能导致 Agent 无回复或工具链中断。
- P0：模型注册表与生产 fallback 配置必须一致，图片 fallback 必须支持多模态。
- P0：Node 24 影响构建、测试、生产镜像及全部 GitHub Actions 工作流。
- P0：预约成功回执与群邀请位于候选人关键转化链路；错误话术会让候选人在兼职群中等待面试链接。
- P0：接管顺序必须保持“候选人回复先送达，随后暂停托管并告警”。
- P1：无单独面试群备注的岗位不得产生额外接管；既有兼职群自动邀请行为必须保持。

### 部署顺序与回滚

- 部署顺序：同步生产 fallback 配置；合并 Release PR #815；合并自动生成的正式发布固化 PR；等待 tag、GitHub Release 和部署完成；执行生产健康、容器、模型、群语义及告警核验。
