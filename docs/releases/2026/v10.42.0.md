## 2. 范围与风险

### 变更摘要

- **本版本唯一代码改动**：`scripts/deploy-remote.sh` 增加 `docker build --network=host` 一行，绕开生产机 `docker0` 网桥的 PMTUD 黑洞，修复构建期拉包 `read ETIMEDOUT`。
- **实际投递面远大于该行**：v10.41.0 已打 tag、已发 GitHub Release，但**两次部署均失败、从未上线**。生产当前仍运行 `v10.40.0-keyrot-86d71dc-20260807045349`。本次发布将使生产从 v10.40.0 直接跳到 v10.42.0，**v10.41.0 的全部载荷随本次首次进入生产**。

> ⚠️ 因此本版本的风险评估**不等于**「一行 shell 改动」，而应按 v10.41.0 的完整范围看待。v10.41.0 的变更摘要、高风险区域、P0/P1 策展与证据**全部继续适用**，见 `docs/releases/2026/v10.41.0.md`，本文不重复抄录。

### 高风险区域

- **P0｜v10.41.0 全量载荷首次入生产**：候选人事实裁决、手机号/籍贯/城市、约面与改约、工具残片守卫、咨询口径等，全部随本次首次面对真实流量。承接 v10.41.0 的 `P1-WAIVER-01`（未执行真实 Agent 回放）残余风险。
- **P0｜凭据**：`FEISHU_APP_SECRET` 仍未轮换，继续按 `SEC-EXC-01` 放行（到期 2026-08-14）。**本次发布不改变该项状态，也不重置其到期日。**
- **P1｜构建期网络隔离降级**：`--network=host` 使构建期 RUN 可访问宿主机本地端口。本项目构建仅 `pnpm install --ignore-scripts` + 编译，风险低；属临时绕行，撤除条件已写入代码注释。
- **P1｜部署链路本身**：本次是连续第三次部署尝试，前两次均在 Dockerfile 第 9 步失败。若本次仍失败，说明宿主机出站问题不止于网桥 MTU。

### 部署顺序与回滚

- 部署顺序：
  1. [#980](https://github.com/huajune/cake-agent-runtime/pull/980) 经完整 CI 合入 develop。
  2. 合并 Release PR [#982](https://github.com/huajune/cake-agent-runtime/pull/982)，固化底账、CHANGELOG 与 tag `v10.42.0`。
  3. tag 触发自动部署。**关键前提**：服务器从 release tag 检出 `source/` 后执行 `deploy-remote.sh` 与 Dockerfile，故 `--network=host` 必须随新 tag 才生效——这正是本版本存在的原因（重跑 v10.41.0 无效）。
  4. 部署完成后核验健康检查与容器状态；因载荷等同 v10.41.0，按其 P1 项做发布后观察。
- 回滚版本：`v10.40.0-keyrot-86d71dc-20260807045349`（当前生产运行版本，内置新 Supabase publishable key）。
- 回滚条件：构建仍失败；容器无法起；Agent 出现事实污染、隐私追问、工具残片泄漏、预约假成功或错误咨询口径。
- 回滚动作：应用/镜像回滚至上述镜像。不得恢复 `chat_messages` 公开敏感列权限，不回滚凭据处置。
