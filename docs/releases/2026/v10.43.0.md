## 2. 范围与风险

### 变更摘要

- **本版本唯一代码改动**：`Dockerfile` deps 阶段新增 `ARG NPM_REGISTRY` + `ENV npm_config_registry`，将 npm 与 pnpm 的包源切到 `registry.npmmirror.com`；订正 `deploy-remote.sh` 中已被证伪的 MTU 注释；删除临时诊断工作流。
- **本次是第三次投递尝试**。v10.41.0 与 v10.42.0 均已打 tag、已发 GitHub Release，但**两者都因构建期拉包失败而从未上线**。生产至今运行 `v10.40.0-keyrot-86d71dc-20260807045349`。

> ⚠️ 本版本的风险评估**不等于**「Dockerfile 两行」，而应按 v10.41.0 的完整范围看待——其载荷随本次首次进入生产。v10.41.0 的变更摘要、高风险区域、P0/P1 策展与证据全部继续适用，见 `docs/releases/2026/v10.41.0.md`。

### 故障定性（有实测数据，非推断）

2026-08-07 生产机只读探测：

| 目标                     | 结果                                       |
| ------------------------ | ------------------------------------------ |
| `registry.npmjs.org`     | ❌ HTTP 000，`connect=0.000000s`，45s 超时 |
| `registry-1.docker.io`   | ❌ HTTP 000，`connect=0.000000s`，45s 超时 |
| `registry.npmmirror.com` | ✅ **HTTP 200，0.73s**                     |
| `api.github.com`         | ✅ HTTP 200，0.29s                         |

`connect=0.000000s` 表示 TCP 连接根本没建立，与 MTU 无关。**此前「docker0 网桥 PMTUD 黑洞」的判断已被 v10.42.0 部署证伪**——加了 `--network=host` 仍同样失败（135.9s，同一错误）。GitHub 通说明不是整机断网，是 npmjs 与 Docker Hub 这两个境外目标连不上；该机 `daemon.json` 早已配置 20 个国内 Docker 镜像源，**npm 是最后一个仍在直连境外源的环节**。

### 高风险区域

- **P0｜v10.41.0 全量载荷首次入生产**：候选人事实裁决、手机号/籍贯/城市、约面与改约、工具残片守卫、咨询口径等，随本次首次面对真实流量。承接 v10.41.0 的 `P1-WAIVER-01`（未执行真实 Agent 回放）残余风险。
- **P0｜凭据**：`FEISHU_APP_SECRET` 仍未轮换，继续按 `SEC-EXC-01` 放行。**本次发布不改变该项状态，也不重置其到期日（2026-08-14）。**
- **P1｜供应链**：引入第三方 registry。需放在实情里看——该机已依赖 20 个第三方 Docker 镜像源运行。pnpm 版本仍钉死、`--ignore-scripts` 保留、`strictDepBuilds` / `allowBuilds` 不变、integrity 校验照常生效。
- **P1｜构建期网络隔离降级**：`--network=host` 保留（理由见 P0-03）。属临时项，撤除条件已写入代码注释。

### 部署顺序与回滚

- 部署顺序：
  1. [#990](https://github.com/huajune/cake-agent-runtime/pull/990) 经完整 CI 合入 develop。
  2. 合并 Release PR [#986](https://github.com/huajune/cake-agent-runtime/pull/986)，固化底账、CHANGELOG 与 tag `v10.43.0`。
  3. tag 触发自动部署。**关键前提**：服务器从 release tag 检出 `source/` 后执行 `deploy-remote.sh` 与 Dockerfile，故换源必须随新 tag 才生效——重跑 v10.41.0 / v10.42.0 均无效。
  4. 部署完成后核验健康检查；因载荷等同 v10.41.0，按其 P1 项做发布后观察。
- 回滚版本：`v10.40.0-keyrot-86d71dc-20260807045349`（当前生产运行版本）。
- 回滚条件：构建仍失败；容器无法起；Agent 出现事实污染、隐私追问、工具残片泄漏、预约假成功或错误咨询口径。
- 回滚动作：应用/镜像回滚至上述镜像。不得恢复 `chat_messages` 公开敏感列权限，不回滚凭据处置。

## 7. 遗留事项与修订记录

- **三次失败的处置**：v10.41.0（两次部署失败）与 v10.42.0（一次部署失败）均已打 tag、已发 GitHub Release 但**从未上线**，不得被误读为已生产验证。三次失败**全部**死在换容器之前，生产无任何停服窗口。
- **一次错误判断的记录**：`--network=host`（v10.42.0）基于「docker0 MTU 导致 PMTUD 黑洞」的推断，该前提未经实测即被采用，随后被部署证伪。教训已固化为本次流程：先只读探测拿数据，再改代码。
- **`SEC-EXC-01` 延续（未处置）**：`FEISHU_APP_SECRET` 仍未轮换，明文值仍存在于本仓库全 refs Git 历史且仍然有效。到期日 **2026-08-14 保持不变，不因连续发版顺延**。三项补偿控制均未开始。完整记录见 `v10.41.0.md` §7。
- **换源撤除项**：出站恢复后经 `--build-arg NPM_REGISTRY=https://registry.npmjs.org` 即可切回。
- **`--network=host` 撤除项**：补测容器经 `docker0` 对 npmmirror 的连通性后即可删除，恢复构建期网络隔离。
