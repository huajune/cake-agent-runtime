## 2. 范围与风险

### 变更摘要

- 修复排班类型短标签与候选人周频/日内时段语义串线，补充语义评审停摆看门狗。
- 在岗位数据零证据、线上面试位置、筛选拒绝翻案、经历造假教唆、日期错配、结算周期、转人工承诺和内部工具残文等链路增加确定性守卫。
- 收紧岗位 `jobId` 血缘、学生身份先筛后推、失效面试取消、AI 面试时间、城市/年龄/姓名/健康证等会话事实的证据门槛。
- 修复 Geo 行政区裸名与道路/街道/公园通名冲突，并补齐 BadCase `暂搁置` 状态保护。
- 入库 BadCase 分析、周报与架构图资产；周报显式日期按运行时本地自然日解析。

### 高风险区域

- P0：岗位、排班、薪资、距离、面试与预约事实必须有当前工具或历史权威证据，守卫不得漏拦或误改写。
- P0：筛选拒绝、学生身份、失效岗位、预约失败和转人工副作用必须保持终局一致，不能继续承诺失败动作。
- P0：会话事实形状门与 Geo 扫描不能把整句污染写入档案，也不能误杀真实行政区名称。
- P0：飞书 BadCase 已裁定为 `暂搁置` 时，单门测试证据不得覆盖运营状态；只有双门通过才可转 `已解决`。
- P1：守卫规则数量与异步语义评审链路增加后，需关注误拦率、评审覆盖率和告警噪音。

### 部署顺序与回滚

- 部署顺序：实现 PR 依次合入 `develop` → 集成回归与正式测试资产闭环 → 发版底账定版 → 元数据 PR → Release PR → tag / GitHub Release → 自动部署生产 → 通知与生产回验 → `master` 回同步 `develop`。
- 回滚版本：v10.37.0。
- 回滚条件：生产容器不健康、岗位/面试事实编造复发、守卫产生阻断性误拦、`暂搁置` 被错误覆盖、语义评审或岗位查询链路不可用。
- 回滚动作：应用回滚到 v10.37.0；无数据库与配置回滚动作；保留测试证据并停止错误飞书状态回写。
