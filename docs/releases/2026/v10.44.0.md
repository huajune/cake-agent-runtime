## 2. 范围与风险

### 变更摘要

本版本载荷以 [#1000](https://github.com/huajune/cake-agent-runtime/pull/1000)（候选人档案域统一）为主体，另含五个较小 PR：

- **#1000 候选人档案域统一**：候选人事实的解析、证据裁决、信号识别与岗位语义收口到 `resolution` 域，`memory` 回归存储职责，`agent` 运行时持有回合实例与 `TurnLedger`；新增 claim/evidence 管线与 LLM 逐字摘录证据纪律。**同时携带 8-11 第三批守卫硬规则下线**（详见下节）。无 migration。
- **#999 清理显式 any 并启用 lint 门禁**：`@typescript-eslint/no-explicit-any` 升为错误级，清理 19 处边界类型债；修复结构化异常非字符串 `message`/`code` 进响应字段、日志脱敏返回 `unknown` 丢失输入形状两处类型风险。
- **#1001 禁止主动询问候选人户籍信息**。
- **#1008 岗位查询显式 `location.range` 在本地距离过滤生效**：修复入参 schema 承诺可显式扩大半径、实际被业务阈值静默截断的契约矛盾。
- **#1010 补 handoff 承诺对账两处生产真阳词形**：后继规则 `handoff_promise_reconciliation` 补齐旧规则退役后无人接管的两个词形。
- **#996** 补齐 v10.41.0 / v10.42.0 / v10.43.0 发布结果（纯文档）。

### 高风险区域

- **P0｜候选人档案域重构首次入生产**（#1000）：改动覆盖候选人事实解析全链路——城市/区域/定位、品牌意图、学生身份、健康证、姓名/手机号、性别补充、简历读取的证据来源与置信度口径全部经过重排。失败模式为候选人事实错判或跨轮丢失，直接影响岗位召回与报名。
- **P0｜四条守卫硬规则下线首次生效**（随 #1000）：`handoff_promise_without_handoff`、`job_facts_without_any_lookup`、`screening_rejection_override`、`settlement_no_evidence_assertion` 的实现与目录注册被删除。这四条在生产持续活跃至本次发版前（`handoff_promise_without_handoff` 近 14 天 83 次命中），下线后其拦截行为立即消失。
- **P0｜`handoff_promise_reconciliation` 首次 enforce**（无 shadow 期，2026-08-14 裁定）：命中后不改文本，改为挂人工介入 sideEffect——暂停托管 + 飞书通知 + `handoff_events` 落库。按 8-17/18 两日生产命中实测推算，**预计日均 4~5 次暂停托管与真人 ping**，需运营侧确认可承接。
- **P1｜`location.range` 行为变更**（#1008）：显式传入的半径此前被静默截断至 `max_recommend_distance_km`（约 10km），本次起生效。模型主动放宽半径时召回量与距离分布会变化。
- **P1｜lint 门禁与类型收窄**（#999）：`no-explicit-any` 升错误级属静态检查，运行时风险集中在被收窄的异常处理与脱敏路径。

### 部署顺序与回滚

- 部署顺序：
  1. 六个实现 PR 均已经完整 CI 合入 develop。
  2. 合并 Release PR [#998](https://github.com/huajune/cake-agent-runtime/pull/998)，固化底账、CHANGELOG 与 tag `v10.44.0`。
  3. tag 触发自动部署（服务器从 release tag 检出 `source/` 构建）。
  4. 部署完成后核验 `/agent/health`，并按下列 P1 项做发布后观察。
- 回滚版本：`v10.43.0`。
- 回滚条件：候选人事实出现系统性错判或跨轮丢失；守卫下线后出现无人拦截的编造投递物；`handoff_promise_reconciliation` 暂停托管频次显著超出日均 4~5 次预估致运营无法承接；召回量因 range 变更异常。
- 回滚动作：重新部署 `v10.43.0` tag。**注意**：#1000 的候选人事实结构为前向演进，回滚后新写入的档案结构不保证被旧代码完整读取，回滚前需评估已积累档案数据。

## 7. 遗留事项与修订记录

- **遗留事项 1｜`job_facts_without_any_lookup` 真阳形态暂无承接方**：该规则下线后，「模型宣称的搜索范围与工具实际执行范围不符」这一形态无人拦截。生产实证 `batch_6a850deece406a6aee24c149`（2026-08-19）：模型传 `range=20000` 但工具实际只查 10km，仍向候选人宣称「扩到 20 公里查了没有」，同回合语义 shadow 判 pass 未接住。诱因（range 被静默截断）已由 #1008 修复，但过度宣称本身仍缺确定性对账。建议后续做「回复宣称范围 vs 工具 `querySummary` 实际范围」窄规则——两侧均为结构化数字，符合既定「有确定性证据基的规则才留」判据。
- **遗留事项 2｜`handoff_promise_reconciliation` 无 shadow 期直接 enforce**：按 2026-08-14 裁定执行，发布后需按 P1-01 观察触发频次与运营承接情况。
