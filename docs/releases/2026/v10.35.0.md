## 2. 范围与风险

### 变更摘要

- 修复 AI SDK v7 禁止在 `messages` 中传 `system` 角色后，shadow 语义出站审查全模型失败的问题；统一使用 `instructions` 与 `prompt`。
- 收口 BadCase 反馈口径：Web 入口新增影响级别与期望处理方式，场景分类切换到 13+2 白名单，写入侧归一非白名单标签。
- 加固面试群边界：需真人补发面试群时，预约成功后暂停托管并加急提醒，不再发送普通预约成功卡。
- 增加 BadCase 治理双门禁、证据台账与默认 dry-run 的治理文档同步能力；生产缺少治理列时仅降级告警。
- 修正 repair 回归闸：P1/P2 回退首版，P0/泄漏类两版均不投递；查岗明确为空时允许删除幻觉岗位。

### 高风险区域

- P0：语义审查自 v10.34.0 起档案断流；若修复无效，`output_semantic_review_degraded` 会继续出现，`guardrail_review_records.semantic_reviews` 无新记录。
- P0：AI SDK v7 prompt 契约覆盖生成、修复与守卫链路；残留 `messages.role=system` 会导致调用在 Provider 前失败。
- P0：面试群接管位于预约成功链路；必须先完成候选人侧正确口径，再暂停托管并提醒真人补发。
- P0：repair 回归处理不能把已被 P0 守卫否决的首版重新投递。
- P1：历史分类值与新 13+2 口径并存；发布后需重跑一次性迁移清理空窗期旧标签。

### 部署顺序与回滚

- 部署顺序：合并 #827 → 合并 develop 元数据 PR → squash 合并 develop→master Release PR → 等待固化、tag、Release 与部署 → 验证语义审查恢复 → 重跑分类迁移。
- 回滚版本：v10.34.0。
- 回滚条件：模型调用/工具链失败、候选人主链异常、预约后接管顺序错误、语义审查仍持续全量降级，或分类迁移产生非白名单值。
- 回滚动作：应用回滚至 v10.34.0；分类异常时根据 `scripts/badcase-category-cleanup/category-backup.json` 制定恢复操作，未单独确认前不批量回写。
