## 2. 范围与风险

### 变更摘要

- 地理识别补齐沈阳/佛山业务足迹，并修复定位分享轮内坐标锚点和硬约束合并顺序。
- 报名后复聊增加真人介入证据闸，真人已经回复后停止提醒和面试后追问。
- 人工升级对账认可 `raise_risk_alert`，回复修复上下文补入当前时间锚。
- 发版通知增加内容质量闸门，地理方案文档同步到实际交付状态。
- Web 的 BadCase 反馈入口改为可选“问题原因”，并补充 P0/P1/P2 与期望处理方式。
- 飞书 BadCase 表新增独立“问题原因”及治理、测试证据字段，避免继续把测试错误码堆入运营分类。
- 测试集与验证集证据采用双门禁；两侧最新评审都通过才自动写“已解决”。
- 每次状态或证据变化后，自动把进展累计追加到飞书《BadCase 治理进展同步》，不再生成周报。

### 高风险区域

- P0：生产飞书表结构和 Web 反馈写入必须前后兼容；新增字段采用 expand-only，不删除旧“分类”列或历史选项。
- P0：文档写入失败不得回滚已成功的 BadCase 状态写入，重复事件不得重复追加。
- P0：定位分享、真人介入和人工升级均处在消息决策关键链路，必须保持既有负例不误命中。
- P1：历史证据回填默认 dry-run，且明确关闭文档同步，避免存量清账形成虚假“最新进展”。

### 数据库、配置与外部依赖

| ---------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------ |
| Migration / RPC / 权限 | N/A                                                                                | 无数据库结构变化                              | N/A                            |
| 环境变量 / 运行时配置  | 新增 `FEISHU_BADCASE_GOVERNANCE_WIKI_TOKEN`、`BADCASE_GOVERNANCE_DOC_SYNC_ENABLED` | 先配置 Wiki token，文档只读检查通过后开启写入 | 关闭同步开关即可停止文档写入   |
| 外部服务 / 权限        | 飞书 Bitable 与 Wiki/Docx 机器人权限                                               | 已验证目标文档可读写；发布时创建缺失表字段    | 新字段保留不删除，旧代码会忽略 |

### 部署顺序与回滚

- 部署顺序：先扩展生产飞书表字段；再发布应用；验证反馈写入与文档 dry-run；最后打开文档同步开关并重启。
- 回滚版本：v10.32.0。
- 回滚条件：Web 反馈无法提交、BadCase 状态错误关闭、文档重复追加或应用启动失败。
- 回滚动作：关闭文档同步开关；回滚应用到 v10.32.0；保留新增飞书字段，不执行破坏性删列。
