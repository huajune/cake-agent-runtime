## 2. 范围与风险

### 变更摘要

- 收资、筛选、预约和候选人信息披露统一到 collection/resolution 合同，守住“未成功 booking 不宣称成功”和“敏感拒因不外泄”。
- 复聊链路增加面试前确认、推店未回拉群收口与面试后入职跟进，并保留 testing 策略源的外部动作隔离。
- Guardrail 收窄班次承诺判定，避免否定、复述和跨分句上下文误杀。
- 上下文装配完成缓存、膨胀哨兵、段落归类与无损瘦身治理；记忆重组为两层模型，并增加 bot 账号维度、摘要数组与独立沉淀水位。
- 工具、文档与发布元数据按当前实现清理；58 条冻结 BadCase 的执行、评审、Dashboard 同步与可回写飞书记录证据保留。
- v11 收口批（#1043/#1045/#1047）：收资身份四槽改环境级 labelId 锚点；疑似多人代报闸；守卫移除第二语义审查并收敛规则链；precheck 契约 BREAKING 收口——candidateClaims 删除、formAnswers 唯一入口、labelTitle 原文直出、身份同义词回退、面试时间转运、unmatchedAnswers 回执、清单瘦身、组合式确认识别。

### 高风险区域

- **P0｜数据库与应用同批切换**：首个 migration 将 `profile_facts`、`preference_facts`、`summary_data` 重命名；后续 RPC 签名和 bot 维度也发生变化。迁移后的 schema 不兼容当前 v10.44.0，普通“回滚旧镜像”不能作为迁移后的可靠回滚方案。
- **P0｜记忆隔离与懒迁移**：长期记忆按稳定托管账号隔离，摘要从 object 平铺为 array，沉淀水位迁入独立列；风险为跨 bot 召回、旧形状覆盖并发新写和幂等水位失效。
- **P0｜收资/预约边界**：风险为重复收集、错字段写入、筛选后仍预约或无 booking 成功却声称已提交。
- **P1｜模型行为变化**：system sections 重排与上下文窗口由 60/8K 调整为 120/24K，需持续观察缓存、token 膨胀与关键规则注意力。
- **P1｜外部证据可追溯性**：58 条 BadCase 中有 8 条飞书源记录已被外部删除；运行与评审证据完整，但无法回写不存在的原记录。

### 部署顺序与回滚

1. 本 PR 只推进到代码审批；在生产切换获得单独授权前，不合并 #1018、不创建 tag、不触发部署。
2. 切换窗口内先确认 v10.45 镜像可构建、生产配置已裁定、数据库备份/恢复路径可用。
3. 暂停会写入长期记忆的流量，按文件名顺序执行 5 个 migration，并立即切换到 v10.45 应用。
4. 恢复流量后验证健康检查、长期记忆读写、摘要沉淀、收资与 booking，再继续观察日志和 Dashboard。
5. 第一个 migration 应用后，不得直接回滚到 v10.44.0；失败时优先前向修复。确需回退时，必须使用已演练的数据库恢复/逆迁移方案与匹配的应用版本。
