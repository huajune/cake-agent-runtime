## 2. 范围与风险

### 变更摘要

- 收紧候选人档案事实来源：昵称/自动招呼语不再写成真实姓名、手机号或健康证等候选人事实。
- 补齐残障资格疑问句式的 Pre-Agent 静默转人工，禁止自动化筛选或模板式拒绝。
- 为岗位查询、预检与邀约建立确定性时机闸门，避免未选岗、失效岗或未完成核验时越级拉群。
- 阶梯薪资计算基数缺失时不再自行推断，改走 `salary_admin_inquiry` 人工确认；健康证回答必须同时覆盖面试与入职两阶段。
- 补齐零岗位证据却输出量化岗位事实的语义审查入口，并统一距离、薪资、发薪日与班次的硬事实信号。
- 增强失效岗位记忆剔除、转人工当轮 `job_id` 底账、品牌数字写法归一化、悬空承诺与工具残文守卫。
- 修正 Dashboard 总览失败口径：`processing` 保留在总消息数，但不再计入失败数或成功率分母。

### 高风险区域

- P0：候选人身份、岗位、薪资、健康证、预约和邀约事实必须有当前权威证据，不能由模型补空。
- P0：残障身份披露或资格询问必须在生产入站入口静默暂停并交由真人接续，不能暴露 AI 或自动拒绝。
- P0：守卫改写不能被“结构塌缩”误判后回退到含编造事实的首稿。
- P0：失效岗位不能继续留在焦点岗位/推荐池并被用于预检、预约、邀约或转人工归因。
- P1：品牌汉字数字与阿拉伯数字归一化不能误伤真实品牌或造成跨品牌串台。
- P1：Dashboard 统计函数口径变化不能影响函数签名、总消息数或既有调用方。

- 回滚条件：生产容器不健康、候选人回复出现事实编造/工具残文、静默转人工失效、邀约越级、失效岗位继续被使用，或 Dashboard 统计函数异常。
