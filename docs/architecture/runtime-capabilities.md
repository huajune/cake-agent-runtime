# 运行能力与恢复边界

本文描述六阶段改造后的代码职责。部署默认仍为观察档，七套在途工单口径保持原行为。代码合入、数据库迁移、生产发布和执行档启用是不同步骤。

| 能力 | 所有者 | 保证与边界 |
| --- | --- | --- |
| 工具动作声明 | `tools/tool-contracts.ts` | 效果、重放、时效、次数和门禁均由契约声明；未声明的动态工具不能注册 |
| 业务重复报名 | 报名/预检工具与预约快照 | 复用已有工单回执；跨账号、不同岗位及查不到的情况分别表达 |
| 持久执行纪律 | `biz/action-execution` | 同意图先登记再派发；未知不重做；成功与本地同步分别记账 |
| 输入归属与回复 | `biz/reply-execution`、渠道 delivery | execute 保存逻辑回合与最小结局，普通回复 single_pass；各模式按消息 ID 精确确认，追踪号继续独立 |
| 生成与重试保护 | `llm/tool-replay-fence.ts`、Runner/Generator | 异常保留最小动作证据；已成功或未决动作不因上层重跑再次执行 |
| 候选人进度 | `biz/candidate-progress` | 工单事实按人共享，聊天状态按聊天隔离；无证据即 unknown；窗口先比较再评审 |
| 当前行动许可 | `biz/action-permit` | 入站、worker、生成前和实际派发前各自检查当前许可 |
| 后台任务 | `infra/queue` | 持有者令牌租约、有界等待、共用队列参数及用尽告警 |

## 外部成功与本地失败

外部操作没有与本地数据库共享事务。派发前保存意图和归属，外部成功后保存结果及 `local_sync=pending`；后续只补本地投影。超时、进程退出或写回失败都不能自行证明外部失败。成功证据无法落库时，已保存的 executing 行仍可被发现；恢复只能查证或交人工。

自动核实有数量、时间和尝试预算。晚到可靠证据仍可结算原派发尝试；人工结论经过受控 RPC 留审计。没有经过验证的请求终态查询、幂等契约或可信回调时，系统保留未知，不承诺跨平台的全局恰好一次。

## 回复与后台恢复

execute 输入归属在生成前保存，新普通回复使用 `single_pass`：不持久保存完整回复正文或分段计划，重启后不重生成、不续发原话。发送 API 明确返回 `errcode=0` 表示已受理，可继续后段；未知结果停止后段，不盲重发。受理不等于候选人已收到或已读。确认 Redis 输入失败后，只修复原消息 ID 的确认，不调用模型或重发。历史 `frozen` 记录仍保留原计划恢复能力，直到未结义务与回滚保留期均结束。

observe/off 同样按实际接纳的消息 ID 确认 pending；确认重试不使用列表条数，replay 每次读取当前列表并按消息 ID 去重。队列过期重建后，新输入不会被旧轮确认裁掉或被旧下标跳过。缺少身份或无法解析的项保留并记录错误，不猜测归属。

群任务和复聊使用各自任务链，不创建主聊回合、计划或动作记录，不受主聊 cutover 约束。主聊报名成功后的提醒入队仍是主聊本地收尾，到期执行由复聊负责。群任务以 `sendAttempted` 保护已有发送尝试，重试和重启均不重发部分成功或结果未知的消息。所有任务仍须检查场景、时效与当前行动许可。已退役的群发送计划备份只用于隔离审计，不得直接恢复到当前队列；需要恢复旧任务时，须先恢复与其匹配的隔离处理逻辑。

## 开关与部署顺序

1. 按序单独验证并执行动作迁移 `20261021090000_agent_action_records.sql`、业务事件补账迁移 `20261021093000_action_ops_event_projection.sql`、回复迁移 `20261021100000_reply_turns.sql`、预约轮询索引 `20261021110000_booking_poll_seek_index.sql`、本地预约版本保护 `20261021130000_version_booking_projections.sql`。事件迁移依赖原有 `ops_events`，投影迁移依赖原有长期记忆表。观察档部署同样需要这些 RPC，不能连带执行其他历史待迁移文件。
2. 普通回复还需 `20261106160000_ordinary_reply_single_pass.sql`，读回策略必须明确。应用保持 `ACTION_EXECUTION_MODE=observe`，核对观察数据、账号身份、回调路由及恢复告警。容器停止宽限期为 90 秒，覆盖默认 60 秒应用排空预算。
3. 单独验收主聊边界前输入的处置、execute 义务与补账能力后，再设置输入切换边界并启用 execute。群任务和复聊不作为主聊切换义务移交。回退必须保留边界和已有执行记录的恢复能力。
4. 进度窗口当前固定 legacy，只记录差异；新统一口径需要另行评审和实现切换，不能随动作开关改变。
