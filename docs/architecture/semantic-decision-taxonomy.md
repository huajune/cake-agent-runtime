# 语义判定三分法：重设计版

**最后更新**：2026-08-12（对代码核实：路径 / 服务名 / 表名 / 常量）

> **体系定位**：候选人认知体系的**判定机制轴**——一个判定该用正则、LLM 标签位还是向量。
> 与之正交的记忆本体与证据采信两轴，权威见
> [candidate-profile-domain.md](./candidate-profile-domain.md)
> （§1 域宪法）。共同宪法：确定性守门、LLM 只降级不放权（HC-2）。

## 1. 三分法原则（继承不变）

| 判定类型 | 特征 | 正确形态 |
|---|---|---|
| **结构/格式信号** | 键值对、时间后缀、引用块、手机号、错误码、枚举 | 正则/结构解析 |
| **极性/意图分类** | 开放自然语言归入封闭标签集 | LLM 封闭标签位 |
| **相似度/检索** | 答案集是开放数据（案例库/历史回复），判定本质是距离 | 向量（本系统当前空集，见 §5） |

判档口诀：**答案是格式 → 正则；答案是标签 → LLM；答案是距离 → 向量。**

代价不对称补充（继承）：误报无害的点（如 critical-turn-guard，误触发只多一条提示词禁令）
保持宽松正则不迁移；"判错即事故"的点才有迁移优先级。

## 2. 第二档的正确形态：抽取顺风车，不建独立仲裁器

**活样板是 `brand_intents`**（LLM 极性轨，生产运行中）：抽取调用的结构化输出里放一个
封闭标签位（`polarity: positive|negative|browse_all`），搭每回合既有抽取调用的顺风车，
零新增 LLM 调用，输出经确定性验证（品牌库标准化）后进状态机。

语义档迁移的统一模板，四要素：

1. **封闭标签位**：`LLMEntityExtractionResultSchema` 加一个 enum 字段 + 逐字 quote
   ；
2. **搭车**：不新增同步 LLM 调用——与"投递路径不加 LLM 实时判断"裁定（2026-07）零碰撞；
3. **claim 通货**：产出为 model 章 claim 进裁决底盘，字段待遇由 policy Record 决定；
   语义分类不需要权威章（`AUTHORITATIVE_PRODUCERS` 不含 model 是宪法，档案权威仍归
   确定性渠道），无 HC-2 碰撞；
4. **正则退守与冻结**：既有正则降为快轨/降级兜底并冻结——新 badcase 不再加正则分支，
   先看 shadow diff，模型判错改标签位提示词。

**提案人定则**：

- LLM 轨（抽取模型、主聊模型工具入参）在身份族字段上是**提案人，不是事实源**——提案必须过确定性验证（值可从候选人原话推导）才能入档。**信任只发给验证器：提案人可以弱，验证器必须硬**——换抽取模型从此只是性价比问题，不再是安全问题。
- 主聊模型纠错 resolution 错误的合法形式是**举证改**（带 quote 的 claim 进裁决底盘，复算通过即采信、按让位表压过错误值），永远不是**口径改**——上下文富 ≠ 权威高：8-10 事故中把臆造值搬进工具参数的，正是全系统上下文最富的主聊模型。
- **两病分治**：上下文贫瘠导致错认（指代接错/漏改口），治法是上下文增强；模型冲动导致编造（零上下文也能编出整套档案），治法是门，喂料救不了编造。
- 用户定音：resolution 域的价值 = **解析 & 治理 & 裁决**——解析产提案、治理设门、裁决定采信，三道工序合起来就是"信任只发给验证器"的物理实现。

**常量核/变量壳定则**：

- resolution 的**常量核**与模型能力曲线无关：①词典（brand 目录/geo 行政层级/合法枚举——业务数据接地，非语言理解，再强的模型也不知道 brandId 10023 是谁）；②政策（多源让位表——geocode/自报/回填谁优先是业务信任排序，不是智能问题）；③账本（证据链追溯——报名是对门店的业务交割，组织需要"凭什么信"）。
- **变量壳**=验证门宽度与正则快轨覆盖面，**应随模型战绩收缩**，且收缩通道已标准化：shadow 对照 → 数据赢 → 掌舵/放权。已走完全程的实例：brand 极性轨（shadow_diff 赢后规则 reducer 物理删除）；在走：labor-form；探针/quote 门松紧由 A1 复测数据调。"相信模型会越来越强"的工程表达=信任按战绩发放的上位通道，不是凭信念直接放权——模型每强一代，壳自动薄一层。
- 永不收缩的最后一毫米：**不可逆动作前的确定性对账**（报名提交前的出处核对）——checklist 不是不信飞行员。

**对账定则**：

- 历史教训链：主聊模型翻车 → 立硬规则约束 → **规则本身成为更大的假阳源**。
- 定则：**规则不配判智力，规则只配对账。**禁止用确定性规则评判模型输出的语义质量（"算不算承诺/有没有出处/是不是歧视"=拿正则猜语义）；规则的合法职权是把输出与系统权威持有的事实**对账**：工具回执 vs 成功宣称、日期算术、格式标记、精确词表、候选人原话账本 vs quote。
- 本定则回溯解释 8-11 硬规则生死名单：存活五条（booking_receipt/date_reference/internal_leak/phrase_leak/store_status）全是对账，下线全族全是智力评判。
- 边界澄清：**quote 复算是对账不是智力评判**——查"原话账本里有没有这句话"是账本查找，不评判模型理解对错；故与提案人定则无冲突。
- 约束模型的正道三条，无一含"规则判分"：改它看见的（提示词纪律/上下文增强）、对账它交出的（quote/回执/词典）、离线环调它（shadow 复盘修正）。

**闸门侧"放行位仲裁器"**（正则要 reject 时同步调 LLM 复核翻案）降格为预留位：仅当某闸门
的拒绝被 shadow 数据证明大量误伤、且该判定无法搭抽取车时才立项，须单独过快环裁定豁免评审。
当前无立项。

### 2.1 首发迁移：labor-form 意向三态

选它的理由：初版盘点的 badcase 密度王（6a334d26/6a61c97c/6a61d124…每例一个豁免正则）；
`LaborFormIntentDecision = set|clear|ignore` 是现成的封闭标签集；`resolution/labor-form`
的意向正则就是"规则匹配语义"的典型病灶。

形态：抽取 schema 加 `labor_form_intent` 标签位（intent + laborForm + quote）→ 与规则轨
`resolveLaborFormIntent` 判定对照，diff 落 `agent_execution_events`
（eventType=`semantic_track_diff`）→ **shadow 期规则继续掌舵** → diff 数据支撑后翻转，
意向正则冻结退守。

### 2.2 后续候选（按 shadow 数据与 badcase 实证排期，暂不立项）

- 品牌极性长尾（LLM 轨已在，观察规则轨假阳是否仍值得收缩）；
- "要求 vs 自述"歧义句式（岗位要求被记成候选人自陈的字段族）；

  三处修复后需复测再定）；
- 输入层风险/转人工开放变体（**不能搭抽取车**——risk-intercept 在管道入口先于抽取，
  如立项须走放行位预留评审）。

**身份作证族特判**（`student-identity.ts` 的 STUDENT/SOCIAL_CLAUSE_RE 整句白名单）：
这族正则是"格式工具打语义仗"的化石标本——语气词枚举 `(?:哈|哦|呀|啊)?` 等可选组是
死锁事故（6a448d09，漏认即同题追问/转人工）后一轮轮拓宽的疤痕。但 is_student 是
欺诈压力最大的字段（洗白教唆 6a50827c、抽取污染 P0 复发 7-28），**模型轨有前科，
不得接管作证**。正解是拆掉"漏认即死锁"的恐惧根源，而不是继续加词：

1. 自发自陈白名单**即日冻结**——新句式不再加可选组；
2. 识别不了的长尾由**模型轨接**（抽取 is_student + explicit_provenance quote，已存在）——
   **不得为识别缺口新增追问**；确认问答解析器只在业务本就要问
   （岗位筛选门槛）时作为**答案解析器**存在，不作为兜底提问的理由；
3. 白名单收缩（删既有拓宽组回退核心句式）需 badcase 实证支撑，暂不做。

## 3. 格式档欠的一条纪律：证据回传

格式判定用正则是对的，但规则轨在主动丢弃自己最值钱的副产品：解析器明知命中位置，
却存静态标签当 evidence（`put('name', parseName(text), '原文结构化姓名/我叫')`）。
**正则是全系统唯一能免费给出完美可复算证据的轨道。**

目标状态：规则轨一切产出物（collected-fields / rule-track claim / 存根 evidence）的
evidence 一律为**命中片段**（truncateEvidence 后），静态规则名只作片段不可得时的 fallback。
A1 基线 B 度量（可提取摘录 36.3%、逐字命中 75.8%）为对照基线。

### 3.1 出站守卫证据基结论（防复活条款，8-11）

`job_facts_without_any_lookup` 下线的根因是**证据基错误**：它以本轮 toolCalls
为证据基，天然把跨轮复述与候选人海报（visual sheet）判成编造。此结论固化为条款：
**若语义档观察期后真阳残余量值得重建"无出处岗位事实"防线，重建的唯一合法形态是
「出站文本中的量化断言 vs TurnLedger（fetchedJobs/visualFactSheets/累计工具产物）+
档案 的确定性比对」**——即 claim 世界 quote 复算的出站同构。禁止再写任何
turn-scoped 的出处正则。settlement_no_evidence_assertion 的跨轮/引用块假阳同此病根。

## 4. 距离档：空集裁定（2026-08-11）

对初版 §2.3 的四个向量场景做必要性重验，**无一过线**：

| 场景 | 重验结论 |
|---|---|
| badcase 相似案例召回 | 治理效率增益非生产缺陷；需要时一个离线脚本即可，不值运行时基建 |
| 语义复读检测 | 逐字层 day1=0，"措辞重写残留"零实证；出站侧机器在 repair 复盘冻结令下 |
| 岗位回指打分 | includes 计分制工作正常，badcase 密度低 |
| 测试资产去重 | 边缘 |

**裁定：不建任何向量基建**（无 pgvector、无 embed 角色、无 embedding 表）。
"可以用向量"不等于"该用向量"。

**反场景清单**（明令禁用向量的三个位置，防将来自发引入）：

1. **极性/否定**：embedding 对否定是瞎的（"我是暑假工"vs"我不是暑假工"余弦极近）；
2. **品牌同音**：embedding 编码语义不编码语音，"啃得鸡"≈"肯德基"语音距离零、语义距离远，
   拼音相似度（`fuzzy-recall.ts`）是正确工具；
3. **quote 复算归一**：防臆造防线只准字符层折叠，语义相似匹配=拆防线。

**留门判据**：未来提议引入向量须同时满足——答案集是开放数据（非封闭枚举）、
badcase 实证在手（不是假设性残留）、离线或 observe-only 路径。三者缺一不受理。

## 5. 治理规则（继承并更新）

1. **词表冻结**：已被封闭标签位覆盖的判定点，对应正则/词表冻结——新 badcase 不加分支，
   先看 shadow diff；`signal/dialogue.ts` 肯定应答底座是全系统唯一词表居所，禁再开分店。
2. **新判定点准入评审**：先过判档口诀 + 代价不对称分析，评审记录写 PR 描述。
3. **不可逆路径确定性优先**：booking 提交、取消工单、拉群、暂停托管的最终闸门必须有
   确定性层；LLM 只可出现在"复核放行"预留位，永不"独立放权"（HC-2）。
4. **回归资产**：标签位翻转 enforce 时，被替换正则的命中样本转 test-suite curated 集；
   shadow 翻案样本持续补入。
5. **成本闸**：搭车形态天然零增量调用；放行位预留如立项须单独设调用上限与降级。
