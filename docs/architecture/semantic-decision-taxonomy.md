# 语义判定三分法

**最后更新**：2026-08-26

> 一个判定该放在结构解析、既有 LLM 理解，还是检索层，先看答案的形态。候选人档案与
> 证据采信的域宪法见 [candidate-profile-domain.md](./candidate-profile-domain.md)。

## 1. 判档原则

| 判定类型 | 特征 | 正确形态 |
| --- | --- | --- |
| 结构/格式与回执对账 | 键值、时间、引用块、枚举、目录、错误码、工具结果 | 结构解析或封闭确定性规则 |
| 极性/意图分类 | 开放自然语言归入封闭标签集 | 复用已有 `extract_facts` 或主 Agent 理解 |
| 相似度/检索 | 答案集是开放数据，问题本质是距离 | 检索；当前运行时没有向量判定点 |

口诀：**答案是格式就解析，答案是标签就复用现有 LLM，答案是距离才考虑检索。**

规则不负责评价模型“是否理解得像人”。规则的合法职权是检查可复算事实：目录是否命中、
quote 是否来自原文、工具是否成功、回执字段是否与回复一致、格式是否有效。

## 2. 封闭标签搭现有抽取调用

开放语义需要封闭标签时，优先放入既有 `extract_facts` 结构化输出，不新增同步 LLM 调用：

1. schema 使用枚举标签和逐字 quote；
2. 输出进入现有 claim/验证底盘；
3. 枚举、quote、品牌目录等确定性门仍负责验收；
4. 正常抽取结果是权威意图，规则轨只在抽取降级、缺失或非法时兜底；
5. 不再建设 shadow diff、第二模型仲裁或并行语义评分链。

### 2.1 品牌意图

`brand_intents` 负责 `positive | negative | browse_all` 等复杂品牌极性。品牌实体必须经
`resolution/brand` 目录标准化后才能写状态：

- 正常抽取：图片解析结果 + 经验证的 `brand_intents` 生效；规则极性不得覆盖；
- 抽取失败或结果非法：才使用既有品牌极性规则兜底；
- `brand_alias_fuzzy_match_ignored` 只对账工具已经给出的高置信目录回指，不从回复中做
  开放式品牌抽取。

### 2.2 用工形式意图

`labor_form_intent` 的封闭结果为 `set | clear | ignore`：

- 正常抽取：合法且 quote 可验证的结果直接生效；旧 `preferences.labor_form` 与规则
  turn hint 不得覆盖；
- `ignore` 必须保持 ignore，不能被同轮正则重新解释成 set/clear；
- 抽取失败、缺失或非法：回退 `decideLaborFormIntent()` 的封闭显式句式；
- 回退只覆盖明确选择、拒绝、接受和有限的“有某类岗位吗”请求；岗位事实问句、身份登记
  描述和复杂改口留给 `extract_facts`。

`semantic_track_diff` 已删除；不再维护双轨对照或一致率观测。

## 3. 主 Agent 负责连续对话理解

需要完整对话上下文的判断由现有主 Agent 完成，例如：

- 候选人是否对前几轮推荐不满意；
- 是否应该继续推荐、正常收口或提议拉群；
- 一般性承诺、措辞质量、岗位介绍是否自然；
- 普通角色扮演请求是不是恶意 Prompt Injection。

工具只保留结构化闸门：`noMatchScript` 表示本次查询无匹配，`invite_timing_gate` 校验拉群
城市、去重、时机和候选人同意。工具不再扫描历史文本、计数无岗轮次或推断情绪。

## 4. Output Guardrail 的边界

Output 只保留三类能力：

1. **确定性格式**：异常模型输出、内部标记泄漏、元叙述旁白、精确分段去重；
2. **封闭高风险词形**：身份/经历造假教唆、歧视性筛选、主动籍贯探问、无依据名额承诺；
3. **工具回执对账**：预约、改约、线上面试位置、明确 no-match 后的门店状态猜测、高置信
   品牌回指。

Output 不调用第二个模型，不运行 semantic reviewer/shadow，不通过 observe 规则猜开放语义。
handoff 承诺在 `turn-outcome` 与真实副作用对账；日期和结构一致性由格式化及 repair regression
gate 处理。

## 5. 不可逆动作仍由确定性门把关

模型可以提出动作，但 booking、取消、改约、拉群和暂停托管的最终执行必须通过已有 Tool gate
与结构化回执。上下文丰富不等于事实权威；不可逆动作前的来源、身份、jobId 和状态校验不会
随模型能力提升而删除。

## 6. 禁止项

- 不为开放语义新增正则分支；
- 不新增输入分类 LLM、输出 reviewer 或 shadow diff；
- 不用向量判断否定、品牌同音或 quote 真实性；
- 不把 precheck 的 `candidateClaims/formAnswers` 契约问题混入本改造；
- 不用新观测、Dashboard、Rule Catalog 或人工标注流程替代代码边界。
