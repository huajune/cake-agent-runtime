# 群任务与复聊的外部动作恢复

本实现依赖统一动作底账、逻辑回合与精确回调入口。默认观察档不切换生产行为；启用执行档及设置切换边界由独立上线流程完成。

## 群任务

- Bull 原任务时间和执行编号形成持久身份；日期、场次、群号、消息段形成业务意图。同一意图更换内容会被拒绝，不能通过新建执行编号绕开。
- 主文本、小程序卡片、跟随文本分别登记 `group_task.message`，冻结顺序、内容和间隔。执行计划同时写入 Redis 与原 Bull job；发送前必须完成持久化。任务没有可靠企业、会话或原始时间时，执行档停止发送。
- HTTP 接受只记 `executing`。回调必须通过统一渠道入口验证企业凭证，并精确匹配企业、账号、会话、请求号、消息类型及文本/卡片内容，才确认成功。缺少字段或不可信旧小组路由均保留未知，不能用查空推断未发送。
- 主消息成功后只继续剩余段。未知段不会自动换请求号、换内容或重发；核实成功后恢复原失败 Bull job，继续同一冻结计划。已成功的段不再调用外部接口。
- 执行档每次实际发送前重新核对 bot 与企业归属、租约和原任务 24 小时时限；过期任务只能补账，不新发剩余段。
- 群发送标记、品牌历史和结果摘要是本地投影。外部成功不因 Redis 写失败变成发送失败。恢复持有统一会话租约，每次写入前检查归属；品牌历史原子去重。
- 汇总把未确认结果单列“待核对”，不纳入成功或确定失败。飞书预览与汇总卡本身仍走原通知链路，不宣称已纳入动作底账。

## 复聊

- 业务意图使用 `sessionId:scenarioCode:anchorEventId`；原锚点时间进入 `inputOccurredAt`，不使用重试时间或临时 trace 作为新意图。普通回合传入稳定逻辑回合号生成锚点事件。
- 生成前通过 `beginReply` 打开同一持久回合。已有计划直接采用原文，使用统一 `wecom.reply_segment` 动作与唯一回调入口。`ReplyDeferredError` 表示执行中/未知，不记为一次新的确定失败，也不生成新文本。
- 投递前保存恢复所需的安全渠道身份与原任务；不保存令牌。确认成功后的触达频控写入原子去重，并以最大时间更新冷却，补账不会多算一次触达或把冷却时间倒退。
- 执行档先扫描 SQL 持久待投影索引，最多 25 条、25 秒任务预算；原任务最小上下文在 `ReplyTurn.recovery.task` 首次打开时冻结，仅含原身份、业务引用、原 trace、时间与场景参数，不含 token、完整历史或工单快照。Redis 未知槽仅作为旧任务兼容入口，扫描最多 100 个键、5 页、5 秒。
- 所有原段都确认成功时只修触达和本地后续排程，当前关闭托管也不抹除已发生事实。纯补账不新发升级拉群邀请，转人工核对；该邀请原正常路径保持原逻辑。
- 尚有剩余段时复用完整原 `process` 校验，包括当前总开关、场景灰度、候选人新消息、权威工单、时间窗口和频控。内容固定，但权限不固定。`dispatchDueAt` 固定为原任务预定时间；兼容旧 Bull 任务只使用原 timestamp + delay，不以恢复时间重新起算。动作 `recoveryWindowStartedAt` 取这一冻结时间，24 小时后不新发剩余段；原报名/输入时间仍用于切换与 90 天边界。
- 已确认成功先补齐后续排程，再记触达 sent，最后完成 SQL 投影；任何一步失败仍保留 pending。取消、部分成功或 provider 确定失败不能算成 sent。新转人工或升级拉群不由纯补账自动触发。
- 旧未知槽没有可靠原计划、回调证据不足、查不到记录均保持未知并告警。Redis 触达恢复资料保留 3 天，只是辅助缓存；SQL pending 上下文跨过这段 TTL 仍可按索引恢复，90 天清理也不删除未完成投影。原回调可唤醒持久恢复，不借助槽过期重发原动作。

## 恢复归属与本地记账

普通回复与复聊恢复共用主聊的 Redis 会话租约。恢复最多执行 30 秒，在段发送、锚点写入、排程、触达记账、settle、逐条输入 ACK 前续租检查；失去归属后保留未完成计划。Redis 与数据库之间没有跨系统原子 fence，最终仍依赖动作表 CAS、精确 messageId ACK、幂等事件与单调锚点。

开场事件绑定原 logicalTurnId。事件已提交而排程失败时，再次精确读取同一企业、会话的开场事件，恢复仍认作同一个开场回合并排原锚点；不会因 duplicate 响应误记成普通回复。执行档须等待开场及工具/回复锚点排程确认后才 ACK，恢复不重新调用模型。每次恢复生成新的 trace，保留原逻辑回合与原生成证据。

## 验证范围

本地故障测试覆盖真实动作执行器的分段去重、payload 冲突、HTTP 接受后的等待、成功后投影失败、恢复租约丢失、只恢复原任务；复聊覆盖冻结计划复用、关闭权限后补账、恢复时重新执行业务闸、旧未知转人工、触达频控幂等与大页扫描续读。未向企微、飞书或生产数据库发测试写入。

外部请求在没有权威终态证据时不能保证恰好一次；实现通过保留未知和停止自动重发避免以猜测制造重复动作。普通安全告警、预览卡和汇总卡继续沿用原链路。
