## 4. 按行为判定 execute（本轮重新审查）

验收对象是最终待发布代码。普通回复以发送 API 明确 `errcode=0` 为受理成功，继续原计划并确认输入；不要求自发回调、对端已读或邀请后实际入群。未决请求仍须保留原身份，不能凭当前工单/成员状态冒充原请求终态。

| 必须保证的行为 | 验证方式 | 发布边界 |
| --- | --- | --- |
| 正常普通回复完成全部段落及原输入确认 | 企业/小组 API 明确成功、无回调的真实 SQL 服务链路 | 受理不等于送达/已读；复聊和群任务保留现有独立确认策略 |
| 重试、并发、重启不重复副作用 | 真实 SQL 并发、冻结输入/计划、未知不重派、实际数据库重启 | 不要求在生产制造超时或重启事故；供应商与模型使用替身 |
| 外部成功后的本地失败可补账 | 结果写入失败、修复队列、Redis CAS、版本墓碑与输入 ACK 的故障验证 | 本地失败不得改成外部失败；不可恢复时保留未决并交人工 |
| 当前权限变化能阻止新的派发 | 派发前权限/租约检查、冻结路由、迁组停止 | 权限改变不抹掉已经明确成功的事实 |
| 未知结果有处理入口 | 原 attempt 的人工裁定/审计 SQL；告警失败仍保留有退避的扫描重试 | 自动供应商查询不是必要条件；未核实不得重发或伪造成功 |
| 切换和回退保护原义务 | 旧 observe 不升级；旧 execute 后续段、请求号和计划在 off/observe 下仍受执行约束 | 发布时统一配置并保留 cutover，不能退回不识别账本的旧版本 |

生产自然样本用于确认接口响应形态、实际运行表现和发现异常，不要求每个故障分支都真实发生一次。历史 unknown、明确业务拒绝、某个错误码没有新样本、没有对端已读证据，都不能单独推导出 execute 不合格。若故障注入发现行为错误，应修复该错误并复验，不通过新增真实环境验收条件替代代码修复。

切换配置属于发布步骤：本次不修改生产模式。执行切换前仍需发布本轮代码、核实全实例一致、设定输入生效时间，并处理跨边界旧输入和旧群任务；历史观察计划不能改成 execute 计划重放。当前开关是进程级，不能承诺按企业/动作类型灰度，也不能混配实例充当灰度。回退 observe 保留 cutover、数据库账本和本轮恢复实现。
