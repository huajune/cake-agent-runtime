# 收资流字段去重与一次成型

> 2026-08-11 | 状态：**已批准**（8-11 用户批准，实施任务=implementation-guide 收尾-14） | 起源：7-27 用户裁定"收资字段集与分波策略由专门产品需求承接"；8-11 生产实测补齐实证

## 1. 问题与实证

候选人体验侧的"被反复盘问感"，实测**不来自身份识别器**（8-11 扫描：7 天 56 个被问身份的会话中 48 个只问一次，识别一次命中、无死锁复发），而来自收资流本身。完整实证样本 chat `6a75aab3ce406a6aee711d22`（2026-08-07 10:09-10:13，五分钟内）：

1. **已知信息再确认**："系统标你是男生，方便确认下性别吗"——系统已有性别仍要求确认；
2. **碎问**：性别年龄刚答完，下一条单独再问"学生还是社会人士"；
3. **字段重叠**：候选人答完"社会人士"1 分钟后，11 项大表单里仍含"**学信网学籍状态**"——与刚回答的身份问题语义重叠；
4. **模板重发**：候选人追问两个岗位细节后，11 项表单整体逐字重发（收资模板重发 badcase 族复发）。

## 2. 需求三条

### R1 已知字段不再问

收资表单/追问生成前，先对照会话档案（sessionFacts/长期档案/工单回填）做**字段级扣除**：已有高置信值的字段不出现在表单里，只在最终确认时一并复述（"帮你带出来确认下：姓名X、电话X…对吗"——生产已有此形态的正例，chat `6a79748c` 的预填确认体验良好，应成为唯一形态）。

- 低置信（medium）值的处置：预填进表单让候选人纠错（"年龄：37（如有误请改）"），而不是留空重问。
- 性别等 enrichment 已补齐的字段：不再作为提问项，仅在与岗位硬门槛相关时随确认清单复述。

### R2 字段集去重叠

对收资字段清单做一次语义查重，同义/包含关系的字段合并为一个提问项。已知重叠对：

- 「身份：学生/社会人士」 vs 「学信网学籍状态」——二选一（保留哪个由业务定：学信网口径更严，但仅部分岗位需要；建议默认问身份，学信网仅在岗位明确要求学籍核验时出现）。
- 其余重叠项需运营侧过一遍全量字段清单（customerLabel 衍生字段是历史重灾区，参见"岗位筛选条件≠收集字段"既有裁定）。

### R3 表单一次成型、追问只催缺口

- 一个岗位的收资表单**一轮内一次成型**：筛选性字段（身份/年龄等硬门槛）先问、通过后再发资料表单的两段式保留，但每段内部不拆散提问。
- 候选人部分作答或中途追问岗位细节后：**只简短催缺失字段**（"还差学历和健康证两项哈"），禁止整表重发。precheck collect_fields 指令已有"刚发过只简短催填"分支，需求验收要覆盖"候选人中途追问岗位细节"这一分叉（实测正是该分叉触发整表重发）。

## 3. 不做什么

- 不动身份识别白名单与抽取链路（归三分法方案与档案域战役，已各自有任务）。
- 不为"识别缺口"新增任何追问（8-11 裁定，写入 semantic-decision-taxonomy.md §3.2）。
- 不改岗位筛选门槛本身的问询必要性——岗位要求学生身份/年龄时问一次是业务必需。

## 4. 验收口径

- 复扫指标：重复收资率（同字段同会话被问 ≥2 次的会话占比）、表单重发率（同表单 24h 内逐字重发次数）——以 8-11 扫描口径为基线。
- 定性回归：chat 6a75aab3 形态（已知性别再确认/身份与学籍重叠/整表重发）进 test-suite 策展集。
