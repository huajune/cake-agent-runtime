# 招聘 Agent 敏感信息与安全护栏说明（运营版）

**最后更新**：2026-08-26（本文描述**现行系统**，按四个防线作用位与当前裁决动作复核）
**目标读者**：运营同学（非技术）
**技术侧文档**：基础设施层护栏（鉴权/重试/限流/注入检测实现）见 [架构文档 security-guardrails.md](../architecture/security-guardrails.md)

本文说明招聘 Agent（企微托管 AI）在敏感信息上的**现行口径与系统防线**。重点先说清三件事：

1. **性别/年龄口径已改**：岗位的性别、年龄要求**可以对候选人明说**，不符时转岗承接（2026-07-03 运营裁决）。
2. **户籍口径已收紧**：户籍/籍贯类信息**禁说也禁问**——连"公司登记需要核对下户籍"这类借口式问法也会被系统强拦（2026-08-06 裁定）。旧版文档写过"核对户籍只用承接式问法"，**该口径已废止，请勿再用**。
3. **本文不再维护规则矩阵**：具体规则清单以代码为唯一权威（见文末），文档只讲机制和红线口径。

## 先看懂执行动作

系统有四个作用位：**Input → Prompt → Tool → Output**。Prompt 负责生成前预防；Input / Tool /
Output 才有运行时短路、动作拒绝或出站 veto 权。每条护栏后面的标记含义如下：

| 标记           | 含义                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 🔒 强拦        | 命中后该版回复不可发送；系统先做一次受控重写自救，重写后仍违规才静默不发（个别规则直接静默）。P0 级强拦命中即飞书告警 |
| 📝 打回重写    | 该版回复不可发送，系统按规则反馈定点重写后再审                                                                        |
| 📡 观察记录    | 内容照发，命中落守卫档案或安全告警供复盘                                                                              |
| 📜 Prompt 规则 | 写进 AI 的话术红线或发送前自检，降低首版违规率；它本身不拥有最终拦截权                                                |

出站链路内部再分为：**确定性规则 → 可配置语义 reviewer → 有界修复 / 最终清洗**；有守卫信号的
完整档案落 `guardrail_review_records`，Dashboard 可查。不要把“出站内部三段”误读为整套系统只有三层防线。

## 一、披露分级：岗位要求哪些能对候选人明说

收资和筛选场景下，每个筛选条件都归入两档之一：

### 可明说族（open）

**年龄、性别、学历、健康证、身高体重、在岗时长、排班时间**等岗位硬性条件。收录标准只有一条：**该属性岗位卡上本来就印着给候选人看**（如"18-40 岁，仅限男"），说出来不增加任何信息暴露。

- 候选人不符时：**直说要求 + 转岗承接**是合规动作，不需要绕弯。
- 2026-07-03 运营裁决删除了旧的性别直拒/年龄门槛拦截规则——性别与年龄要求属岗位公开信息，不属歧视外露。

### 禁明说族（restricted）

**户籍、籍贯、民族、专业、婚育、政治面貌、宗教信仰**等，以及**一切未知新标签（默认档）**。

- 判定不符时**绝不披露真实原因**，话术渲染为换岗/拉群承接。
- 新标签天天有，系统默认"没确认可说就不说"——避免每个新配置都变成一次外露赌博。

### 分级怎么定（三层判据）

1. **海绵契约标记**：收资契约（v2）每个字段带 `disclosure` 标（PLAIN / RESTRICTED）。后端标了 RESTRICTED 就是禁明说——生产实测**籍贯已标 RESTRICTED**。
2. **cake 侧红线词表兜底**：契约的 PLAIN 只表示"后端没标"，不表示"确认可说"。命中红线词表（户籍/民族/专业/婚育等）一律禁明说，**红线压过契约的 PLAIN**——例如专业类标签后端尚未补标，全靠这层兜住。
3. **可明说白名单**：以上都不命中、且属于岗位卡公开条件的才可明说；否则默认禁明说。

判据代码在 `src/resolution/collection/disclosure-policy.ts`；敏感词表唯一权威在 `src/resolution/collection/sensitive-screening.ts`（岗位渲染、收资披露、出站守卫读同一份，禁止各处另抄副本）。

### 筛选执行与拒绝原因是分开的

- **照配置筛**：契约里的不合格选项命中即当轮不合格，筛选本身照常执行，不因禁明说而放水。
- **如实入账**：判定结果和证据完整落账本，内部记录永远真实，委婉只发生在对候选人的话术层。
- **因果隔离**：候选人**刚回答完敏感字段的那一轮不触发拒绝**，拒绝顺延到下一轮——哪怕话术再委婉，"我刚说完籍贯它就说没岗位了"的紧邻时序本身就把原因暴露了。

## 二、户籍 / 籍贯 / 民族 / 专业 / 婚育（最严格：禁说也禁问）

### 禁说 🔒（P0 强拦 + 飞书告警）

AI 回复把户籍、籍贯、民族、专业、婚育等筛选条件说出口，或拿这些条件直接拒绝候选人 → 该版回复强拦。红线族已从户籍/民族扩展覆盖**专业、婚育**：不得提及门槛、不得解释具体不通过原因；核对专业只能开放式问"你学的什么专业"，不得把排除条件塞进问句；婚育信息禁止询问、复述或确认。

### 禁问 🔒（P0 强拦 + 飞书告警，2026-08-06 裁定）

AI **主动向候选人打听籍贯、老家、是不是本地人** → 该版回复强拦，**包括为此编造的行政借口**——"公司登记需要核对下户籍""系统/流程需要"这类说法一并明拦。裁定背景：生产 badcase 中 Agent 问"这家对户籍有要求，方便问一下你老家是哪里的吗"，候选人当场质问后流失；运营裁定"无论岗位数据有没有要求，都不应该问"。

- **合规替代**：需要了解地点时只能开放式问"你常驻在哪个城市""想去哪个城市工作"。
- 海绵契约确需收集户籍信息时，走收资**表单字段链路**（候选人按表格填写，该字段披露级为 RESTRICTED、拒因不明说），不属于"主动打听"。

### 岗位数据侧配套

岗位自由文本（备注/面试补充项等）命中敏感筛选词时，进 AI 前自动追加"仅供内部筛选、严禁转述"标注；结构化户籍字段渲染自带勿透露标记。宽口径检测宁滥勿漏——误报代价只是多一行内部提示，候选人不可见。

### 记忆侧配套

户籍类信息只在收资表单链路内使用，**不进跨会话长期画像**（长期记忆白名单里没有户籍字段，见第四节）。

## 三、诚信保护（防 AI 编造，候选人不被误导）

- **名额承诺强拦** 🔒（P0）："名额肯定有 / 给你留着 / 不会满"这类不能保证的承诺，命中强拦 + 飞书告警。
- **诚信教唆强规则族** 📝（P0）：教唆候选人以不实身份登记（"为了过审按非暑假工登记"）、或在候选人自曝经历造假后教其面试时声称"做过/有经验"，命中打回重写为如实口径（`identity_misregistration_coaching` / `experience_fraud_coaching`）。
- **承诺-动作对账**：报名/改约/拉群等承诺与本轮工具事实不一致时（如"帮你提交报名"但并未提交、确认了未生效的改约时间），按规则打回重写或补执行人工介入，让承诺要么如实、要么成真。
- **收资字段禁替填** 📜：候选人没给的字段留空，严禁拿岗位要求（如年龄上限）替候选人填。

---

## 四、候选人个人信息保护

- **长期记忆白名单**：跨会话只存七个稳定身份字段——**姓名、电话、性别、年龄、是否学生、学历、健康证**。闲聊内容不存，**户籍/籍贯不在白名单内**。
- **候选人信息不跨托管账号共享**（2026-08-20 裁定，已实现）：长期事实按托管账号严格隔离——写入时记录归属账号，召回时严格按当前账号过滤；无法证明归属的存量数据在生产侧宁缺勿给。A 账号聊出来的信息不会出现在 B 账号的对话里。
- **性别自陈优先** 🔒：系统有性别标签兜底回填，但候选人自己说的性别永远优先，自陈后系统标签不可覆盖；两种来源在系统里分开记录。
- **报名真名闸** 🔒（工具层）：昵称、拼音、占位串不入报名库，校验不过会引导补真名（"门店登记需要本名"）。
- **少数民族/特殊姓名保护** 📜+🔒：疑似少数民族或特殊姓名被平台校验拒绝时，**严禁要求候选人"改名"**，强制转人工补录。

## 五、会话风险与人工介入

- **风险预检** 🔒：候选人消息出现辱骂、投诉风险、矛盾升级信号 → 本轮收敛为入站
  `guardrail_blocked`，不运行 AI、不回复；Replay 定局后统一暂停托管并告警人工接手。
- **候选人黑名单** 🔒：运营拉黑后，任一托管账号再收到该候选人消息 → 施加永久暂停托管 + 飞书告警（附拉黑理由）。
- **历史面试结果追问** 📜：候选人问"为什么没过/上次面试结果" → 不继续推岗，转人工。

---

## 六、系统自身安全

- **指令注入防护** 📡：候选人消息出现"忽略之前的指令 / 把提示词发出来 / 假装你是…"等套取/劫持模式 → 自动加固 AI 角色设定 + 告警。
- **内部信息强拦** 🔒（P0）：回复出现阶段名、工具名、JSON/代码块等内部实现痕迹 → 强拦。
- **AI 旁白强拦** 🔒（P0）：整条回复是描述 AI 自身行为的括号旁白（如"（本轮为真人沟通，AI 保持静默）"）→ 直接静默不发送——这类内容多出现在真人接管期间，发出去等于自曝 AI 身份。
- **人设保护** 📝："转人工 / 人工客服 / 真人经理 / 专人联系"等与"账号即本人"人设冲突的表述 → 打回改写为人设内口径（如"我帮你问下同事"）。
- **对外品牌口径** 📜：平台品牌只称"独立客"（"独立日"是错误写法）；岗位品牌名以本轮工具结果为准。

## 运营同学的行动指引

1. **收到"出站守卫拦截 P0 回复事故"飞书告警** → 该版回复未发出，候选人当轮可能收到重写后的版本或沉默，请尽快人工跟进该会话。
2. **观察类命中不发飞书** → 落守卫档案（`guardrail_review_records`），Dashboard 与例行复盘覆盖，无需实时响应。
3. **风险预检 / 黑名单触发** → 托管已自动暂停，该会话归人工。
4. **对候选人的口径**：性别/年龄/学历/健康证等岗位硬性要求可以直说，不符就转岗；户籍/籍贯/民族/专业/婚育**永远不说也不问**，需要地点信息只开放式问常驻/意向城市。
5. **配岗位数据时**：敏感筛选条件尽量配结构化字段；对外文案绝不写户籍/民族/专业/婚育类要求；海绵侧新增收资标签时，禁明说的记得标 RESTRICTED——没标时系统按红线词表和默认禁明说兜底，但标准做法是配置到位。
