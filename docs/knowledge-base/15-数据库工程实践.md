# 数据库工程实践（Supabase/Postgres）

## 迁移纪律

- 测试/生产双库隔离（`db:push:test` / `db:push:prod`），**先测试后生产**
- SQL 幂等：新建用 `IF NOT EXISTS` / `ON CONFLICT`；但**修改既有定义**（索引/函数）必须 `DROP IF EXISTS + CREATE`——IF NOT EXISTS 只查名字不查定义，会静默跳过（吃过 0 行事故，见 [[14-生产事故复盘集]] 案例 3）
- **迁移与代码发版必须同步**：只发代码不推迁移（或反之）是反复发生过的事故源
- 上线新表后用一条真实写入验证落库，不能只看部署成功

## Schema 设计裁定

- **按维度分表而非宽表**：回合流水 / 执行事件 / 守卫档案 / 复聊触达 / 业务漏斗各自独立表，同 trace_id join——写入方、生命周期、查询模式不同的数据不同居
- **JSONB 存档案、真实列存指标**：大 JSONB（完整 prompt 达 43KB）走 TOAST，高频读取字段必须提列（ttft 事故）
- 字段自带元数据模式：`profile_facts` jsonb 里每个事实带 `{value, confidence, source, evidence}`——比"值一张表、元数据一张表"简单得多，查询也总是一起用
- 大表前瞻：`ops_events` 日增 50 万行时再上分区，不提前过度设计

## Redis 与 Postgres 的分工

判定标准不是"快不快"，而是**丢了算不算事故**：

- 丢了算事故且无 DB 备份的 key（facts / stage / group-task）——这类是"Redis 唯一事实源"，是架构风险清单上的显式条目
- 缓存/协调/队列类（去重、锁、debounce pending）可自愈，丢了最多重复或延迟

有价值的易失数据靠**沉淀**转移到 Postgres（session facts → profile_facts）。

## 连接池

Supabase `max_conns=60` 被 Dashboard 轮询 + 重试风暴打满过全线 522（见 [[14-生产事故复盘集]] 案例 1）；Dashboard 定时预热 + JSONB 裸扫又造成过 Postgres 连续重启（案例 7）。RPC 轮询要有节流，应用重试要有熔断，后台统计必须有固定成本上限。

## 查询与后台任务红线

以下任一项不满足即阻断合入：

1. **降级成本单调下降**：RPC 超时、缺失、熔断或返回异常时，只能读旧缓存、返回空统计并告警；禁止改走全表扫描、分页拉全量或在 Node 重新聚合。主查询因过重失败后再发更重查询，等同自我 DDoS。
2. **定时任务不碰无界明细**：`all`/全历史及 30～90 天长窗口不得进入分钟级预热。长范围必须读小时/日投影；确需明细时由用户按需触发，设置明确起点、statement timeout 和缓存。
3. **每轮有互斥和预算**：cron 必须防 tick 重叠，并限制单轮时间窗、bucket 数、行数和总执行时间。多实例任务使用数据库 advisory lock/分布式锁，不能只靠进程内布尔值。
4. **断更只补洞**：聚合任务按已存在的 bucket 键找缺口，只补缺失小时/日期；无数据的 bucket 也写零值水位，避免每轮重复判断为缺失。禁止因“最新水位过旧”重算整个窗口。
5. **JSONB/TOAST 不做高频统计源**：频繁过滤、排序、分组或展开的字段提升为真实列或预聚合；不得在轮询、预热和 cron 中对大 JSONB 使用 `jsonb_array_elements*`。
6. **重试与熔断按操作隔离**：瞬时错误只允许有上限的指数退避 + 抖动；熔断计数按 RPC/表操作区分，其他健康查询成功不能清零当前失败操作。

### 合入前证据

- 在生产量级、相同索引和数据分布下记录 `EXPLAIN (ANALYZE, BUFFERS)`；确认索引、扫描行数、临时文件和执行时间有硬上界。
- 对 cron/轮询做持续运行验证，核对单位时间调用次数、连接数、累计 DB 时间和任务重叠次数；单次接口延迟改善不能替代持续负载验证。
- 人工演练 RPC 超时、聚合断更和熔断 OPEN，证明失败路径不会发起更重查询。
- 发布后重点观察 `pg_stat_statements`、连接池、CPU/IO、异常重启和聚合水位；异常时先停预热/断载，再考虑扩容。

## 学习要点

前端转后端最容易被考的就是数据库。这套实践的叙事线：**幂等迁移 → 双环境纪律 → 观测验证落库 → 读写路径分离设计 → 查询成本有界且失败成本递减**，每一条都有真实事故背书，比背书本的"三范式"有说服力得多。
