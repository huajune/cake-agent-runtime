# 两层记忆系统（Short-term / Long-term）

## 解决什么问题

LLM 无状态，而招聘对话会跨天、跨咨询持续。系统不把全部历史无限塞进 prompt，而是按作用域分成短期和长期两层；工作记忆与 episodic 摘要是层内结构或计算产物，不再冒充额外存储层。

## 两层与三个时间数

| 作用域              | 内容                                    | 存储                           | 边界                                   |
| ------------------- | --------------------------------------- | ------------------------------ | -------------------------------------- |
| Short-term 消息窗口 | 原始对话窗口                            | `chat_messages` + Redis 热缓存 | 回看 7 天，最多 120 条并受字符上限约束 |
| Short-term 会话状态 | facts、岗位工作台、阶段指针             | Redis `factsv2:*` / `stage:*`  | 3 天；facts 实际多 12 小时沉淀余量     |
| Long-term 关系档    | profile、job intent、episodic summaries | Supabase + Redis 2 小时缓存    | 候选人 × bot 持久关系                  |

固定业务口径是 **7d / 3d / 3d**：消息回看 7 天、会话状态 3 天、闲置 3 天划分咨询段并触发 consolidation。

`turnHints` 只活在当前轮，是规则识别 sidecar；episode 只是消息裁剪和沉淀的计算边界。两者都没有独立存储层。

## 统一召回与 Prompt 消费

`MemoryService.onTurnStart()` 并行取得消息窗口、会话状态、阶段和当前候选人 × bot 的长期关系档，返回 `MemoryRecallContext`。Preparation 随后补齐 snapshot、计算共享裁决视图，再由 memory、turn-hints、hard-constraints 等 sections 消费。

同字段冲突遵循档案域宪法：本轮 accepted > session accepted > profile historical_unconfirmed；置信度只在同作用域内比较。模型可见的 `[会话记忆]`、`[用户档案]`、`[本轮解析线索]` 标签保持稳定。

## Short-term 并发语义

`factsv2:*` 使用 Redis hash，top-level 字段按 field 写入，避免整 blob 读改写造成无声丢更新。事实通常带 `value / confidence / source / evidence` 信封；`facts.brand` 由 `BrandStateService` reducer 独占写入。

岗位候选池、已展示岗位、当前焦点岗位和查询签名属于 short-term workbench；阶段指针虽使用独立 `stage:*` key，仍是 short-term working state，不是程序性记忆层。

## Long-term 与 consolidation

长期关系档以 `(corpId, userId, botUserId)` 隔离：

- `semantic_profile`：身份档案，逐字段置信度守卫合并；
- `semantic_job_intent`：最新咨询段的意向快照，整组覆盖；
- `episodic_session_summaries`：每段咨询追加一条摘要，最多 20 条，确定性淘汰最旧条目；
- `consolidation_watermarks`：独立水位，不属于记忆内容。

闲置 3 天后，delayed consolidation job 先用 DB 最新消息复核边界，再写 profile、job intent 和摘要。摘要只对新咨询段调用一次 LLM；已经落盘的摘要不会被再次压缩或重写。

## 设计权衡

- 结构化招聘事实字段可枚举、需要审计，schema 化状态比向量检索更可靠；默认链路不引入记忆 RAG。
- 消息窗口与会话 TTL 分离：Redis 状态过期后，7 天原文仍可帮助回访重建上下文。
- profile、意向和经历采用不同写法：事实越证越硬，意向以新为准，经历只增不改。
- 收资表单是业务单据，归 `src/tools/collection/`，不属于记忆层。

完整契约、目录和排障路径见 [Memory 当前实现](../../src/memory/README.md) 与 [记忆系统架构与数据流](../architecture/memory-architecture.md)。
