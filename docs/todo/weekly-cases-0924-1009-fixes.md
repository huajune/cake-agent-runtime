## 1. 新会话被当成「漕宝路」回访

- 证据：`batch_6ac85778ce406a6aeef8e575_1791514496458`（10/9 10:54，零工具）；`..._1791514749320`（次轮 geocode + job_list）。事发请求快照含 geocode 教学示例「漕宝路地铁站」，对话消息不含漕宝路
- 根因：模型虚构历史已证实；教学示例诱发属推断（中等置信）。模型自己的回复能经 geocode 自证成为高置信城市事实
- 修复方向：
  - [ ] 随下次发版确认示例清理（3dc34ca1）已生效
  - [x] 位置参数出处观测（#1395）：geocode 记录地址是否能追溯到候选人原话/真人/工具结果，只出现在 Agent 自己消息里时告警；**未拦截**，离线粗估误判约 6.5%，观测两周后再定
  - [ ] 城市写入仍可经模型回复 + geocode 自证，待上条观测结论后决定是否收紧
  - [x] 回放：首轮无位置时 4 次中 3 次正常问位置；1 次模型凭空说已约 M Stand 面试（提示词与记忆均无此内容），属模型首轮编造，另行跟踪

## 2. 肯德基不招学生却回复「接受学生」

- 现象：候选人回「学生」，Agent 未查岗直接回「这家接受学生」
- 证据：`batch_6ac85778ce406a6aeef8e575_1791515076511`（10/9 11:04，零工具）；本轮输入同时含「是否学生: 是」与岗位摘要「学生不接受学生」，不是记忆丢失
- 根因：模型在事实齐全时反向作答；查岗侧过滤只在 job_list 执行，覆盖不到「身份刚确认后的无工具回答」。另有提示词冲突：`src/agent/generator/context/sections/working/hard-constraints.section.ts:176` 写「未写学生限制……按没有额外学生硬限制继续……不得凭空增加门店确认或人工介入」，与 job_list 结果（`duliday-job-list.tool.ts` 约 623-632 行）及 9/23 运营裁定「社会身份要求为空时走人工介入」相反
- 修复方向：
  - [x] 统一口径并删除 hard-constraints 冲突表述，台账已登记（#1396）。按裁定：还有收学生的岗位就推这些，只剩字段为空的岗位才转人工
  - [x] 候选人是学生时，提示词按已推荐岗位的结构化社会身份档位逐岗给结论；新增 observe 哨兵（#1396）
  - [x] 回放：原 case、不限身份反例、字段为空、混合四种均符合预期

## 3. 只想晚到，却被告知「排不上」并引导换岗

  - [x] 时段内晚到/早到不算改约，直接答复可以；已有预约查不到岗位时保留预约、不标失效、不换店（#1397）

## 4. 兼职岗位回复了综合月薪

- 现象：取消黄记煌预约后，Agent 推荐塔克贝尔值班经理时说「月薪3000-4000，时薪25.5起」
- 证据：`batch_6ab4b2cdce406a6aee874892_1790233240971`（9/24 15:00，只调了两次 duliday_cancel_work_order）；「3000-4000 元/月」最先出自真人 9/24 15:05 的手机端消息
- 根因：本轮未查塔克贝尔岗位，直接复述真人历史消息里的数字。`src/agent/guardrail/output/rules/job-fact-reconciliation.rule.ts:46-53` 把取消工单算作「查过系统」的工具，规则只盯零工具轮；且数字在历史中出现过即放行，不核验兼职薪资展示口径。9/17 PR #1322（v11.11.0）的卡片薪资口径修复仍在，本例绕过了卡片
- 修复方向：
  - [x] 薪资出处只认成功查岗/预检与会话记忆岗位摘要，取消等工具不再让对账跳过，真人经理消息不为薪资作证；兼职时薪岗不报月薪（手册 T12 + observe 哨兵）（#1397）

## 5. 佛山「南海桂城上海村」被定位到上海

- 现象：候选人说「南海桂城上海村」，Agent 推荐了上海杨浦区的岗位
- 证据：`batch_6ac76ee6ce406a6aee185fc4_1791455030663`（10/8 18:23）；本轮提示「意向城市:上海（high/rule/explicit_city）」、硬约束「城市:上海」；模型传 `city=佛山`，geocode 仍按当前用户位置锚点纠偏到上海并标为唯一确认
- 根因：`src/resolution/geo/whitelist-scanner.ts:22` 的地名通名后缀含「新村」不含「村」，城市扫描（`geo-text-scan.ts:111`）把「上海村」里的「上海」识别成显式城市；错误结果进入硬约束和位置锚点，与模型的佛山判断冲突时被优先采信
- 修复方向：
  - [x] 补齐村/庄/屯/寨/社区等地名边界（#1395）
  - [x] 跨城纠偏：地址自带区县/街镇时尊重地址；纠到别的城市须逐字回显原地址，否则回到确认（#1395）
  - [x] 回放：「南海桂城上海村」按佛山定位查岗；浦东、嘉定马陆两个上海反例不受影响
