# 业务数据补齐组织 ID

状态为待实施。蛋糕后端负责写入、查询和迁移，运营核对小组、Bot 的归属及生效时间。2026 年 11 月 23 日核对时，测试库已有聊天字段 `tenant_id`，已登记的小组、Bot 和已写入组织 ID 的聊天均为 0。正式库尚待迁移。[租户与账号设计](../product/organization-members-and-business-accounts.md)

- [ ] **本版发版前，验收准备开放的接口。** 在测试库按已核对的 17 个小组、12 个在用 Bot 登记归属。用河南和上海自招各一条新消息核对落库、列表和详情。两位河南员工应看到同一批河南聊天，上海自招员工只看到上海自招的聊天，总部可查看两边。流水、复聊等接口若仍按 Bot 当前的小组取数，先在服务端限定为仅总部可访问。
- [ ] **正式发布时，启用在用 Bot 的聊天归属。** 先执行迁移，按发布当天的目录登记小组、Bot 和生效时间。在开放员工访问前，核验各中心的新聊天写入了预期的 `tenant_id`。
- [ ] **其他业务数据可并行开发，按功能验收。** 为处理流水、用户活动、执行事件、复聊、长期记忆和运营报表补齐组织归属。写入、查询和汇总沿用业务发生时的组织。每项开放前，用一个跨组织交接的 Bot 验证交接前后记录各归原组织和新组织，同一事件重试也沿用原归属。
- [ ] **发版后，分批回填存量。** 对在用 Bot 已核实的历史时段先预览，再回填，按组织核对条数，并验证重跑结果一致。4 个退役 Bot 和 1 个评测标识从回填范围排除，归属未核实的记录仅总部可见。
