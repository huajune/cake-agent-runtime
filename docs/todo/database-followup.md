# 数据库治理待办

11 月 23 日，生产库的 `runtime_storage_enabled` 对五个写入开关均返回 `true`。五个工作包已随 v11.18.0 交付，数据保留与消息趋势换源已随 v11.2.0 交付。[数据库读写约定](../db/database-schema.md) · [工作包与回退演练](../technical/runtime-data-model-acceptance-2026-11-19.md) · [保留策略发布记录](../releases/2026/v11.2.0.md)

| 待办 | 负责人 | 完成条件 |
| --- | --- | --- |
| 生产新写与读取对账 | 后端、数据负责人 | 按相同口径比对五种格式的实际新增字节、详情查询 P95，抽查详情、反馈、聊天与测试导出、转人工日报及动作恢复。把样本范围和差异写入验收记录。 |
| 旧列、函数和索引 | 数据库负责人、外部读者 | 确认主表旧快照列、转人工历史列及其清理任务还有哪些读者。按键验证备份可还原，再决定逐项保留或移除。复核测试执行的三个 GIN 索引、转人工索引与清理函数实际生效的签名和保留天数。 |
| 保留期限与统计口径 | 后端、运营 | 核对一次生产清理结果和各统计页「全部」的聚合耗时，与运营确认消息趋势按逻辑消息计数。核对复聊触达结果保留期限届满后，哪些业务事实还能从事件底账复原。 |
| 原文、摘要与消息标识 | 后端、数据负责人 | 逐个核对聊天原文、候选人姓名、日报摘要的页面权限与导出去向。飞书运营日报使用摘要，其他导出核对必要字段。确认消息分段与逻辑消息的关联、群回调外部 ID 及两个时间字段的读者后，决定是否需调整存储。 |
| 转人工数据质量 | 后端、运营 | 按原因核对兜底码、阶段及岗位和工单 ID 的缺失，区分业务上没有与写入遗漏。重点复核改约、预约冲突的工单关联，以及 `other` 的原因说明。 |

生产旧列清理单独安排。原始审计问题和字段明细保存在[保留策略核查清单](https://github.com/huajune/cake-agent-runtime/blob/v11.18.0/docs/todo/data-retention-policy-unification.md)。组织 ID 的正式迁移与历史回填在[组织归属待办](business-data-tenant-id.md)跟踪。
