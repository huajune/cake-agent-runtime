# 聊天行动许可

`evaluate({ chatId, action, botImId, groupId?, candidateIds? })` 返回是否允许及拒绝原因；暂停时同时返回到期时间，永久暂停为 null。`reply` / `tool` 使用 AI 回复总开关，`proactive` 使用复聊总开关。权限源抛错或账号已撤托时拒绝继续执行。

暂停只查 chatId；candidateIds 只用于跨账号共享的候选人黑名单。小组 ID 缺省时从当前托管账号补齐。按 2026-10-15 现行业务裁定，小组屏蔽只阻止被动回复和工具，主动面试提醒及回访仍可执行；它们仍受聊天暂停、候选人黑名单、复聊开关和账号托管状态约束。

入口、worker、投递前、每个分段发送前及复聊生成前均重新判定。复聊内部的工单解析/对账排程不冒充对候选人的主动触达，不因聊天暂停而丢掉内部恢复任务。系统关闭或权限数据不可用使用独立历史原因，不标记成真人已经接管候选人的问题。入口的候选人黑名单告警/暂停仍由原有规则负责；本服务只做判定。

未来工具执行边界通过同一服务传 `action: 'tool'`；调试和离线评测必须使用明确的测试入口，不伪造真实托管身份。许可不替代外部动作执行记录、幂等键或结果未知时的资源阻断。
