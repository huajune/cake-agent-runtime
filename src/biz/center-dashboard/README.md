# 自招中心运营后台范围

沿用原后台页面、表格、开关和接口，由后端根据来源 IP 限定小组与机器人数据。不增加账号登录、角色表或新的中心管理界面。总部走原入口、原处理器，仍能看到全部小组。

## 维护方式

在现有托管平台的小组说明中，将下面这句独占一行：

```text
河南自招团队成员
```

其他备注可以另起一行。匹配完整文案，不按小组名称或含糊的关键词判断。“非河南自招团队成员”不会命中。

- 新增河南小组：添加这行说明，将对应托管号归入该组。
- 移出河南范围：删除该行，或将托管号移到不带标记的小组。
- 支持多个河南小组，不需要在代码中逐个维护组 ID、机器人 ID。
- 归属缓存 5 分钟，后台每 30 秒检查范围；修改归属后，已打开页面通常最迟约 5 分半钟同步。开关写入前强制重新读取目录核验，不等待缓存过期。
- 小组目录或账号目录读取失败时不扩大权限；没有匹配小组就返回空范围。
- 飞书私聊监控分流使用同一套小组归属；外部通道已配置时，归属读取失败不发送到其他群兜底。

## 可见范围

| 菜单         | 河南范围                                 |
| ------------ | ---------------------------------------- |
| 托管用户     | 本中心机器人对应的用户与统计，只读       |
| 托管开关     | 仅本中心小组开关；不显示、不能操作总开关 |
| 聊天记录     | 本中心机器人会话和消息                   |
| 消息处理流水 | 本中心流水与运营详情                     |
| 二次触发追踪 | 本中心记录、跟进文案与状态流转           |

原页面布局和样式保持。前端按权限展示已有菜单/控件，后端对原接口执行相同范围限制。列表、统计、详情均在 SQL 中按机器人过滤，前端传入机器人或小组 ID 不能扩大范围。同一候选人在其他机器人下的数据不串入；缺失机器人标识的历史记录不补全局查询。流水详情不透传原始请求头、提示词或任意内部 JSON。

用户列表来自范围内聊天记录，token 数来自范围内流水；长期业务趋势读取按机器人落库的日报与运营事件，避免旧会话日统计跨机器人累加。查询窗口最多一年、分页有上限、数据库超时 4 秒、客户端超时 5 秒；失败不回退到全表扫描。

## 执行边界

- `DashboardAccessGuard` 允许明确的菜单接口；中心来源不能访问全局配置、策略、测试或其他写接口。
- 全局拦截器对河南请求进入受限读取分支，总部请求继续使用原处理器；返回结构与原前端契约一致。响应禁止共享缓存。
- 来源取 socket；只对显式可信代理读取其覆盖后的 `X-Real-IP`，不使用客户端 `X-Forwarded-For`。可信代理未给合法来源时拒绝。
- 小组开关沿用 `/config/blacklist` POST/DELETE，只允许 `{id,type:'groupId'}`，后端立即检查组归属。同源 Origin、JSON 和专用请求头均需通过。
- 小组开关通过数据库行锁原子增删目标项，不覆盖整个黑名单，不修改总开关和其他小组；共享缓存短期过期同步，已开始的回复不会被撤回。
- 页面先确认访问范围，范围变化会清空对应查询缓存，避免跨范围复用旧数据。
- 浏览器不再直连 Supabase。聊天与流水保留原显示，通过鉴权 SSE 每 15 秒触发可见页面刷新；不向客户端广播全局业务数据。数据库匿名访问权限必须同步关闭。

## 配置与发布

```dotenv
HENAN_DASHBOARD_IPS=1.193.23.48
HENAN_GROUP_DESCRIPTION_MARKER=河南自招团队成员
```

`DASHBOARD_TRUSTED_PROXY_IPS` 填应用实际看到的代理 socket 地址，不能填办公室 IP、任意网段或 `*`。飞书 URL/签名密钥和海绵 token 仅留服务端，不写入 Git。

应用继续依赖部署入口区分已许可的总部/中心网络，非河南请求保持原有行为，不构成公网身份认证。2026-10-27 只读检查发现 Nginx 的 `cake_whitelist.conf` include 被注释；发布前必须核实实际生效的云侧/入口限制、IPv6 和应用端口旁路，不能据此假定所有公网来源都是总部。不需要新增总部后台账号或再维护一套总部 IP 表。

1. 确认服务端 service-role 配置以及 Cake public schema 没有仍需匿名直连的其他客户端。
2. 先在测试环境应用 `20261027160000`（索引）、`20261027160500`（追踪索引与原子开关）、`20261027160700`（原页面受限查询）、`20261027161000`（服务端专用权限）四个迁移，与前后端一起验证。生产建索引需评估锁等待和窗口。
3. 权限迁移收紧 Cake public schema 中非扩展表、列、视图、序列及函数的 PUBLIC/anon/authenticated 权限，保留 service_role；不能脱离代码单独发布。
4. 数据库匿名绕过关闭后，再将海绵 token 合并进对应成员配置，保留其他成员，并配置飞书通道。
5. 从河南实际网络验证五个菜单、详情隔离、小组开关，以及总部完整访问；用生产数据分布复核执行计划和持续负载。

移除河南 IP 映射会恢复旧行为，不是阻断访问的回滚方式。停用应先撤销部署入口的中心访问许可，保留数据库权限收紧。

后台隔离与通知分流代码仍为本地实现，未部署、未修改生产开关。本地测试及隔离数据库模拟不能代替正式环境迁移和网络验证。
